사용자가

> "이번 달 우리 팀 비용 정산해줘."

라고 하면 agent가 알아서:

1. Google Drive/메일/DB에서 지출 내역 수집
2. 영수증/거래내역 분석
3. 누가 누구에게 얼마를 줘야 하는지 계산
4. 이상한 거래나 중복 지출 탐지
5. 각 사람에게 지급할 금액 산출
6. 사용자에게 최종 승인 요청
7. **PayPal API로 실제 지급**
8. 지급 결과 확인
9. 완료된 거래를 기록
10. 다음 달에도 자동으로 반복

이렇게 하는 거야.

이게 훨씬 **"Agent"스럽다.**

해커톤 자체가 단순 chatbot이 아니라 **실제로 workflow를 수행하는 autonomous agent**를 요구하고 있어. 특히 Taskmaster 트랙이 "complete workflow, not just a chatbot"을 명시하고 있고, 실제로 action을 수행하는 걸 강조하고 있어.

+ 더 발전시키면

**"AI가 사용자의 금융 업무를 대신 처리한다"**가 가장 좋아.

### 🏆 수상 확률을 높이는 차별화 시나리오 제안

단순히 *"A에게 10만 원 보내줘"* 수준의 1:1 송금은 다소 평범하게 느껴질 수 있습니다. **복잡한 의사결정 + 비정형 데이터 파싱 + 자율 정산**이 결합된 시나리오를 추천합니다.

1. **글로벌 프리랜서/외주 자동 정산 에이전트**
    - 슬랙/이메일로 전달받은 업무 완료 보고서나 인보이스 PDF를 비전 모델로 분석
    - 계약서 조건(기한, 산출물 체크리스트)과 대조 후 검증
    - 검증 완료 시 담당자에게 요약 카드 전송 → 원클릭 승인 시 **PayPal Payouts API**로 외주비 자동 지급
2. **스마트 소액 정산 & 인보이스 수납 가디언 (Group / Team Expense Splitter)**
    - 회식/프로젝트 영수증 사진 업로드 시 항목별 참여자 자동 분할
    - 미납자에게 **PayPal Invoicing API**로 맞춤형 결제 링크 자동 발송 및 수납 현황 실시간 트래킹
3. **자율 SaaS 구독 및 비용 최적화 에이전트**
    - 구독 결제 내역을 모니터링하여 중복/미사용 SaaS 감지
    - 에이전트가 해당 구독 해지 또는 다운그레이드 조치를 추천하고 승인 시 대행

#### 심사위원을 사로잡을 핵심 아키텍처 팁

- **Security & Safety Guardrails 강조:** "AI의 환각으로 엉뚱한 금액이나 계좌로 송금되는 것을 방지하기 위해 `사전 확인 카드 UI`, `트랜잭션 한도 제한`, `감사 로그(Audit Trail)`를 설계했다"는 점을 발표에서 강조하면 점수가 매우 높게 나옵니다.

## 그런데 "AI가 바로 송금"은 위험하지 않나?

그래서 **Human-in-the-loop을 넣는 게 오히려 좋아.**

Agent가

> "총 $2,480을 지급하려고 합니다."
> 

라고 판단한 뒤,

**[Approve Payment]**

버튼을 눌러야 실제 PayPal API를 호출하도록 하는 거야.

즉,

```
AI가 판단
   ↓
AI가 송금 준비
   ↓
Risk / fraud check
   ↓
사용자 승인
   ↓
PayPal API
   ↓
실제 송금
```

이렇게.

이게 단순히 안전장치일 뿐 아니라 **제품적으로도 훨씬 설득력 있어.**

특히 금융 agent에서 LLM에게 무제한으로 돈을 움직일 권한을 주는 건 좋은 설계가 아니니까.

4분 데모에서도

**"이번 달 외주비 정산해줘" → Agent가 알아서 자료 분석 → 이상 거래 발견 → 승인 → PayPal 송금 → 완료**

이 한 장면을 보여주면 상당히 강력할 것 같아.

참고로 PayPal의 Payouts는 현재 96개 국가/24개 통화를 지원한다고 되어 있고, 개별 지급은 기본적으로 최대 $20,000 수준이다. 다만 **한국에서 실제 송금 플로우를 구성할 때는 지원 국가/통화와 계정 자격을 별도로 확인해야 해.**

### PayPal API가 실제로 제공하는 것

크게 네 덩어리로 보면 됩니다.

**1. 결제 받기 (Orders / Payments API)** — 결제창 띄우고 승인·캡처·환불. 가장 일반적인 용도지만 "송금"과는 방향이 반대입니다(내가 돈을 받는 쪽).

**2. 돈 보내기 (Payouts API)** — 이게 질문하신 송금에 해당합니다. 이메일이나 전화번호만으로 96개국 수신자에게 보낼 수 있고, 수신자는 PayPal 또는 Venmo로 수령합니다. 한 번의 API 호출로 최대 15,000건까지 배치 전송이 가능하고, 엔드포인트는 `POST /v1/payments/payouts`입니다. 응답으로 `payout_batch_id`가 오고 이걸로 건별 상태(성공/대기/실패)를 추적합니다. PayPalPayPal

**3. 청구·구독 (Invoicing, Subscriptions)** — 인보이스 생성 및 링크 발송, 구독 플랜 생성/취소.

**4. 조회·운영 (Transaction Search, Disputes, Webhooks)** — 거래 내역 조회, 분쟁 처리, 이벤트 수신.

그리고 에이전트 관점에서 중요한 것: PayPal은 **Agent Toolkit과 공식 MCP 서버**를 이미 내놨습니다. 에이전트 툴킷의 전체 도구가 remote MCP 서버에서 제공되며, 토큰 권한에 따라 LLM에게 보이는 도구를 제한하는 기능도 들어가 있습니다. 즉 REST를 직접 감쌀 필요 없이 툴 레이어를 거의 공짜로 얻습니다. PayPal

# 아이디어 구체화

## **1. 타겟 고객 및 초기 포지셔닝**

- **팀 규모 및 법인 형태:** 5~20인 규모의 초기 스타트업, 개인사업자, 또는 대학생 프로젝트/동아리 팀
    - 공금을 관리해야 하는 소규모 그룹 전부
        - (시나리오) 글로벌 프리랜서/외주 인력과 협업하는 3~15인 규모 초기 스타트업
        - (시나리오) 개발/디자인/마케팅 등 프로젝트 단위로 인건비 및 외주비를 매달 정산하는 팀
- **주요 페인포인트(Pain Point):**
    - **법인카드 한도 부족으로 인한 개인 카드 선결제 정산 피로도**
    - 흩어진 문서(Google Drive, 이메일, 슬랙)를 일일이 수작업 대조하고 개별 송금하는 비효율 제거
    - MVP 이후 단계에서 구현 :
        - 영수증 누락으로 인한 부가세(VAT, Value Added Tax) 매입세액 공제 실패
        - 흩어진 SaaS(Software as a Service, 서비스형 소프트웨어) 구독 방치
- **페르소나별 역할 및 니즈:**
    - **지출 집행자/승인자 (대표/재무 담당자):**
        - 중복 결제 및 오지급 리스크 방지
        - 인보이스 대조 및 은행/페이팔 송금에 드는 시간 절약
    - **청구자 (외주 프리랜서/팀원):**
        - 청구 하는 방법은
            - 온라인 : Paypal 기록 알아서
            - 오프라인 : 영수증 첨부
                
                → 알아서 파싱해서 뭐는 공금이다 뭐는 개인적인 일이다 해서 청구서 작성
                
        - 지급 누락 방지
            - 내가 사진을 올려 → 회계(agent)가 보고 인보이스를 작성해 → 돈은 그 영수증 대로 나오긴 할거니까 나는 그 영수증 보고 내가 올린 사진이랑 맞는지만 보면 됨 → 내가 올린 사진에 있던 비용이 영수증에 안 써있음 → 이게 뭐임? 이라고 할 수 있는 느낌?
            - 10개 올렸을 때 8개는 돈을 받았는데 두 개는 영수증에 안써있으면 문제 제기
        - 입금 확인
            - Paypal api
            - 에이전트가 어떤 부분이 지급되었고 거부되었는지 정리해서 보고
        - ~~청구 누락 방지~~ : 보류 (기술적 어려움)

## **2. 입력 인터페이스 및 데이터 수집 방식**

- **접근 채널:** 별도 웹 대시보드 중심인지, 아니면 업무 메신저(Slack, Discord) 챗봇/웹훅(Webhook) 기반 입력인지 결정
    - 집행자 : 웹 대시보드
    - 청구자 : 메신저 웹훅 통한 입력 & 웹사이트에 청구자용 연동 경로 추가
        - **원클릭 승인 폼 발송:**
            - 슬랙/메신저로 개인 DM(Direct Message, 다이렉트 메시지) 전송:
                
                > *"📢 [누락 알림] 8월 14일에 결제된 'AWS Korea ￦145,000' 건의 비용 청구가 아직 안 되었어요. 업무용 지출이 맞다면 아래 버튼을 눌러주세요."*
                > 
        - **사진 캡처 유도:**
            - 모바일에서 영수증 사진 한 장만 답장으로 올리면 에이전트가 OCR(Optical Character Recognition, 광학 문자 인식)로 파싱하여 해당 결제 건과 자동 매칭합니다.
- **영수증 인입 형태:**
    - 이미지/PDF(Portable Document Format) 업로드 기반 OCR(Optical Character Recognition, 광학 문자 인식)
        - (MVP) 제미나이한테 그냥 해달라고 해
        - 영수증 OCR은 향후 발전 방향으로 남기기: Donut (Document Understanding Transformer, NAVER Clova)
    - Paypal API 기반 결제 내역
- 프리랜서 타임시트:
    - 엑셀 파일 슬랙/디스코드로 전송하면 에이전트가 도구 써서 분석

## **3. 핵심 비즈니스 로직 및 에이전트 자동화 범위**

1. **트리거 (Trigger):**
    - 집행자 : (MVP) 버튼 / 추가 명령은 자연어 기반 라우팅
        - 미리 설정할 수 있고
        - 자연어로 매번 요청할 때 마다 설정 바꿀 수 있게
    - 청구자 : 메신저 Webhook
        - 청구자가 영수증을 보내면 바로바로 에이전트 호출해서 영수증 내용을 JSON 형태로 클라우드에 저장. 나중에 집행자가 집행 버튼을 누르면 영수증을 이미지로 처리하지 않고 텍스트로 간단히 처리가 가능하도록
    - ~~사용자가 자연어로 요청 (*"이번 달 외주 개발/디자인 인보이스 정산해줘"*)~~
2. **데이터 수집 (Data Ingestion):**
    - Webhook 걸려서 수집된 청구자들이 올린 영수증 DB에서 기간에 맞는거 쭉 뒤져서Google Drive 내 지정 폴더 또는 이메일에서 이번 달 계약서, 타임시트, 인보이스 PDF(Portable Document Format, 포터블 문서 포맷) 자동 수집
    - **데이터 추출 항목:** 공급자 사업자등록번호, 승인일시, 합계금액, 부가세, 품목명 자동 분류
    - **계정과목 자동 매핑:** "AWS(Amazon Web Services) 결제"를 `지급수수료`로, "팀 회식"을 `복리후생비`로 AI가 자동 분류하는 규칙 수립
3. **분석 및 교차 검증 (Cross-validation & Risk Check):**
    - 비전/문서 파싱을 통해 작업자명, 계좌/이메일, 청구 금액, 작업 내역 추출
    - **이상 탐지:** 지난달 인보이스와 100% 동일한 중복 청구, 계약서상 명시된 단가/상한선 초과 여부 감지
4. **인간 참여형 승인 (HITL, Human-in-the-Loop Approval):**
    - 에이전트가 요약 카드(정산 명세서 + 위험 알림)를 화면에 렌더링
    - 관리자가 이상 유무 확인 후 **[최종 승인 및 송금 실행]** 클릭
5. **실제 금융 실행 (Financial Execution):**

## 6. 보안, 안전 및 가드레일 (Safety & Guardrails)

- **자동 송금 한도 설정:** 1회/월간 최대 송금 가능 금액 캡(Cap) 설정
- **자율 송금 차단 (Mandatory HITL):** LLM(Large Language Model, 거대 언어 모델)이 단독으로 송금을 완결하지 못하도록, 사용자 서명/승인 토큰이 전달되어야만 실행 엔드포인트를 호출하는 보안 구조 확립
- **개인식별정보(PII, Personally Identifiable Information) 보호:** 영수증/인보이스 내 불필요한 민감 정보(여권 번호, 주민등록번호 등) 마스킹(Masking) 처리
- **민감 정보 보호:** 카드번호, CVC(Card Verification Code, 카드 유효성 확인 코드), 주민등록번호 등 PII(Personally Identifiable Information, 개인식별정보) 자동 마스킹(Masking) 처리
- **감사 로그(Audit Trail):** AI가 내린 판단 근거(왜 이 금액이 산출되었는지)와 송금 승인 기록을 투명하게 저장

## 7. MVP 범위 및 데모 준비

**Must-Have (1차 구현 범위)**

- 슬랙 영수증 이미지 → Gemini 멀티모달 파싱 → 청구 항목 생성
- PayPal 결제 원장 ↔ 청구 항목 양방향 대조
- **미청구 건 자동 감지 → 슬랙 DM 발송 → 응답 대기 → 무응답 시 1회 재촉 → 버튼 응답 처리**
- 이상 탐지: 유사 중복 청구 1건 + 영수증-청구 금액 불일치 1건
- 승인 게이트: 승인 토큰 없이는 송금 엔드포인트 호출 불가
- PayPal Sandbox Payouts 일괄 송금
- **지급 결과 대조 → 실패/UNCLAIMED 건 감지 → 취소 후 올바른 주소로 재발송 제안**
- 세무사 전달용 XLSX 출력
- 감사 로그: 에이전트 판단 근거 및 도구 호출 이력 저장

**Won't-Have (Phase 2)**

Google Drive 자동 수집, 청구자용 별도 웹페이지, 계약서 단가 대조, 사업자등록번호 추출, 부가세 공제 판단, 타임시트 분석, Notion 연동, 5년 아카이빙 정책

**데모용 데이터셋**

- 정상 프리랜서 인보이스 2건
- 고의 중복 인보이스 1건 (이상 탐지 시연)
- 영수증 이미지와 청구 금액이 어긋나는 건 1건 (판단 시연)
- PayPal 결제는 있으나 영수증 미제출 건 1건 (추적 루프 시연)
- 미등록 이메일 수취인 1명 (UNCLAIMED → 취소 → 재발송 시연)
- PayPal Sandbox 비즈니스 발신 계정 1개 + 수신 가상 계정 3개

**데모 성립 조건**

- 시계 주입 설계: 며칠간의 대기를 40초로 압축 재생하되, 동일 코드가 실제 시계로 GCP에서 실행된 로그를 병행 제시
- 승인 토큰 없이 송금 엔드포인트 호출 시 거부되는 장면 5초 확보
