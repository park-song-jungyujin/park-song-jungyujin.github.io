## 그래서 Agent란 무엇인가?

- 목표 판단 + 수행까지 직접 실행
  - 동작하고 → 돌아오는 반응을 보고 → 다음 스텝으로 진행하는 일련의 루프를 통제하는?
  - 알아서 판단하고 수행
- 범용적이라기보다 세분화된 목표가 있고
- claude나 지피티나 썼을 때 명령을 내려서 뭐 해줘 하기보다 자동화를 통해 한번에 끝까지 실행해주는
- 세션 단위로 말을 바뀌는게 아니라 클라우드에 대화가 저장되고 세션 기록이 유지된다
- agent가 주도권을 가지는 느낌
  - 챗봇은 사람이 원하는거나 궁금한거를 물어보고 하는 느낌이면
  - 에이전트는 정해져있는 파이프라인 따라서 알아서
  - 프롬프트 엔지니어링 + llm 결과물 파싱해서 tool call
  - 파이프라인 설계가 agent한테 있는 느낌

| 단계 | 설명 | 예시 |
| --- | --- | --- |
| L0 | 물으면 답함 | 일반 챗봇 |
| L1 | 스스로 **읽는** 도구 사용 | 웹서치하는 GPT |
| L2 | 스스로 **쓰는** 도구 사용 | 메일 발송, 파일 생성 |
| L3 | 실패하면 **다시 계획** | 코딩 에이전트 |
| **L4** | **사람 없이 스스로 시작** |  |
| **L5** | **주 단위 상태 유지 + 사용자에게 적응** |  |


## 고려해야 할 점

1. agent의 출력이 맞는지 우리가 판별 가능한가?
2. 시연을 위한 데이터를 우리가 실제로 얻을 수 있는지?
3. 클로드, 지피티를 사용할 때와 다른 명확한 차별점(장점)이 있는지?
    1. 계속 관리해준다..?
    2. 사람을 대신한 판단 - 에이전트의 자율성
4. 실제로 이미 있는 기능인가? (구글 take notes for me 회의 에이전트 같은 기능이 있음. but 이미 있는 기능을 업데이트 하는 방향은 괜춘)
